# gamypad_pc

The **Linux** half of [Gamypad](../README.md) — runs a UDP server, and emulates
an Xbox 360 controller through the kernel's `uinput` subsystem.

Part of the Gamypad monorepo. See the [root README](../README.md) for the
protocol, installation, and how the two halves fit together.

## Layout

```
lib/
├── core/
│   ├── gamepad.dart          translates client messages into device calls
│   ├── gamepad_ffi.dart      dart:ffi bindings to libgamepad.so
│   └── gamepad_server.dart   UDP server, ping/pong, disconnect watchdog
└── pages/
    └── server_page.dart      the whole UI: start/stop, QR code, status

native/                    C++ sources for libgamepad.so (the uinput device)
dist/                      install.sh, uninstall.sh, build_release.sh
linux/CMakeLists.txt       builds native/*.cpp into libgamepad.so and bundles it
```

## How the FFI boundary works

`gamepad_ffi.dart` is generated by hand — keep it in sync with
`native/GamepadApi.cpp` (the `extern "C"` shim). CMake compiles
`native/Gamepad.cpp` + `native/GamepadApi.cpp` into `libgamepad.so`, installs
it into the bundle's `lib/`, and the runner finds it via
`CMAKE_INSTALL_RPATH = $ORIGIN/lib`.

**Never commit a prebuilt `libgamepad.so`.** Build it. A checked-in copy drifts
silently from the C++ sources — that is how the old `scripts/libgamepad.so`
ended up in the repository.

## Build

```bash
# Prereqs (Arch / Debian)
sudo pacman -S cmake clang gtk3
sudo apt install cmake clang libgtk-3-dev

flutter pub get
flutter build linux --release
```

## Package a release

```bash
./dist/build_release.sh
```

Builds the app, assembles `dist/Gamypad/`, verifies the files `install.sh`
needs are present, and produces `dist/Gamypad-x86_64.zip` for GitHub Releases.
`dist/Gamypad/` is gitignored — it is a build product, not source.
